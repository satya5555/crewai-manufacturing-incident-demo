# CrewAI Manufacturing Incident Analysis Demo

A multi-agent AI demonstration built using **CrewAI** and an **Azure AI Foundry-hosted LLM** to analyze manufacturing incidents, perform root cause analysis, recommend corrective and preventive actions, and generate a structured incident report.

## Overview

Traditional LLM applications often send a complete problem to a single model.

This project demonstrates a different approach using **multiple specialized AI agents**.

Each agent is assigned a specific responsibility and the agents collaborate sequentially to process a manufacturing incident.

```text
Manufacturing Incident
        |
        v
+-----------------------------+

| Analyst                     |
```

## What is CrewAI?

CrewAI is a framework for creating and orchestrating collaborative AI agents.

Instead of using one large prompt to perform an entire workflow, CrewAI allows applications to define specialized agents with their own:

- Role
- Goal
- Backstory
- LLM
- Tools
- Tasks

These agents can then collaborate through an orchestrated process.

In this project, CrewAI is responsible for **agent and task orchestration**, while the underlying LLM provides the language and reasoning capabilities.

## Demo Scenario

The demo analyzes a manufacturing equipment incident.

Example input:

```text
During normal operation of CNC Machine M-204, the spindle
temperature increased from 65°C to 95°C within 15 minutes.

Operators noticed abnormal vibration and unusual noise from
the spindle area before the machine automatically stopped.

No maintenance activity had been performed on the spindle
during the previous three months.
```

The same crew can process different incidents because the incident is provided as a dynamic runtime input.

## AI Agents

### 1. Manufacturing Incident Analyst

**Responsibility:** Understand what happened.

The agent analyzes the raw incident description and extracts:

- Affected equipment
- Observed symptoms
- Abnormal operating conditions
- Sequence of events
- Operational impact
- Important technical observations

The agent avoids determining the root cause because that responsibility belongs to the next specialist.

### 2. Root Cause Analysis Specialist

**Responsibility:** Determine why the incident may have occurred.

The agent receives the incident analysis and evaluates:

- Probable root causes
- Supporting evidence
- Contributing factors
- Alternative causes
- Assumptions
- Additional verification requirements

The output distinguishes probable explanations from confirmed facts.

### 3. Corrective Action Planner

**Responsibility:** Determine what should be done.

Using the upstream analysis, this agent recommends:

- Immediate containment actions
- Corrective actions
- Preventive actions
- Inspection activities
- Monitoring recommendations
- Action priorities

### 4. Manufacturing Incident Report Writer

**Responsibility:** Communicate the complete analysis.

The final agent consolidates the upstream findings into a professional manufacturing incident report containing sections such as:

- Executive Summary
- Incident Details
- Observed Symptoms
- Technical Analysis
- Probable Root Cause
- Contributing Factors
- Immediate Containment Actions
- Corrective Actions
- Preventive Actions
- Recommended Monitoring
- Verification Requirements
- Conclusion

## Multi-Agent Workflow

The project uses a **sequential process**.

```text
INPUT
  |
  v
TASK 1
Incident Analysis
  |
  v
AGENT 1
Manufacturing Incident Analyst
  |
  | Context
  v
TASK 2
Root Cause Analysis
  |
  v
AGENT 2
Root Cause Analysis Specialist
  |
  | Context
  v
TASK 3
Corrective / Preventive Action Planning
  |
  v
AGENT 3
Corrective Action Planner
  |
  | Context
  v
TASK 4
Final Report Generation
  |
  v
AGENT 4
Manufacturing Incident Report Writer
  |
  v
FINAL INCIDENT REPORT
```

The output generated by an upstream task is supplied as context to the downstream workflow.

This allows the agents to collaborate while maintaining separation of responsibilities.

## Why Use Multiple Agents?

A traditional approach might use:

```text
Incident
   |
   v
Single LLM Prompt
   |
   v
Report
```

The CrewAI approach separates responsibilities:

```text
Incident
   |
   v
Incident Analyst
   |
   v
Root Cause Specialist
   |
   v
Corrective Action Planner
   |
   v
Report Writer
   |
   v
Report
```

Potential advantages include:

- Clear separation of responsibilities
- Specialized agent instructions
- Explicit workflow orchestration
- Easier addition of tools and specialized capabilities
- Easier extension of individual stages
- More transparent intermediate reasoning artifacts

For simple tasks, however, a single LLM call may still be more appropriate.

## Important Note

The root causes and corrective actions produced by the agents are **AI-generated recommendations**.

They should not be treated as confirmed engineering conclusions without appropriate inspection, evidence, domain-expert validation, and organizational safety procedures.

The purpose of this project is to demonstrate **multi-agent AI orchestration using CrewAI**, not to replace engineering judgment.

## Key Takeaway

> CrewAI enables us to divide a complex AI workflow among specialized agents and orchestrate how those agents collaborate.

In this demonstration:

```text
Agent 1 → What happened?

Agent 2 → Why might it have happened?

Agent 3 → What should be done?

Agent 4 → How should the findings be communicated?
```

Together, the agents transform a raw manufacturing incident into a structured incident analysis and final report.
